# 🔔 WebPageMon — 웹페이지 변경 감시기

지정한 웹페이지를 주기적으로 확인하다가 **내용이 바뀌면 팝업으로 알려주는** 단일 HTML 도구입니다.
서버·빌드·설치가 필요 없습니다. 파일 하나(`index.html`)면 **로컬**에서도, **GitHub Pages**에서도 그대로 동작합니다.

## 주요 기능

- ✅ 여러 페이지 동시 감시 (각각 주기·방식 설정)
- ✅ 변경 감지 시 **화면 팝업 + 변경 내용 diff(− 이전 / + 현재)** 표시
- ✅ **브라우저(OS) 알림**, **소리**, **탭 제목 깜빡임** 알림 지원
- ✅ **CSS 선택자**로 특정 영역만 감시 → 광고·시계 등 오탐 최소화
- ✅ **텍스트 비교(권장)** 또는 **원본 HTML 비교** 선택
- ✅ 설정·기준값을 브라우저 `localStorage`에 저장 → 새로고침해도 유지
- ✅ CORS 프록시 선택 가능 (AllOrigins / corsproxy.io / codetabs / 직접 입력 / 없음)

## 사용 방법

### 1) 로컬에서 실행
`index.html` 파일을 더블클릭하거나 브라우저로 열면 끝입니다.

> 참고: `file://`로 열면 일부 사이트 접근이나 OS 알림이 제한될 수 있습니다.
> 가장 안정적인 로컬 실행은 간단한 정적 서버입니다.
> ```bash
> python3 -m http.server 8000
> # 브라우저에서 http://localhost:8000 접속
> ```

### 2) GitHub Pages로 실행 (자동 배포)
이 저장소에는 `.github/workflows/deploy.yml` 워크플로가 포함되어 있어,
작업 브랜치에 **푸시될 때마다 자동으로 GitHub Pages에 배포**됩니다.
(워크플로가 Pages를 자동 활성화하므로 별도 설정 클릭이 필요 없습니다.)

- 배포 주소: **https://noainred.github.io/webpagemon/**
- 진행 상황: 저장소 → **Actions** 탭의 "Deploy to GitHub Pages" 실행 로그
- 수동 재배포: **Actions → Deploy to GitHub Pages → Run workflow**

> 참고: 조직 정책 등으로 Pages 자동 활성화가 막혀 있다면,
> **Settings → Pages → Source = GitHub Actions** 로 한 번만 지정하면 됩니다.

### 3) 감시 추가
1. **감시할 페이지 URL** 입력
2. **확인 주기(초)** 설정 (기본 60초, 최소 5초)
3. (선택) **CSS 선택자**로 감시 영역 지정 — 예: `#notice`, `.board-list`, `main`
4. **+ 감시 시작** 클릭 → 첫 확인 시 기준값이 저장되고, 이후 변경되면 팝업이 뜹니다

## 동작 원리

```
주기적 fetch ──▶ (CORS 프록시) ──▶ HTML 수신
        └▶ CSS 선택자/본문 추출 ─▶ 텍스트 정규화 ─▶ 해시 비교
                                          └▶ 다르면 ⇒ 팝업·알림·소리·diff
```

이전 내용과 해시(cyrb53)를 비교해 달라졌을 때만 알립니다. 변경 시점·횟수·내용 diff를 함께 보여줍니다.

## CORS에 대해 (중요)

브라우저는 보안상 **다른 도메인의 페이지를 자바스크립트로 직접 읽는 것을 차단**합니다.
그래서 공개 **CORS 프록시**를 거쳐 페이지를 가져옵니다. 기본값은 **자동(여러 프록시 순차 시도)** 입니다.

- **자동 모드(권장)**: AllOrigins → codetabs → AllOrigins(raw) → corsproxy.io 순으로 시도해
  하나라도 성공하면 사용합니다. 한 프록시가 죽어도 다른 프록시로 자동 폴백되어 안정적입니다.
- **Jina Reader**: 페이지의 본문 텍스트만 깔끔하게 추출합니다(텍스트 변경 감시에 적합, CSS 선택자는 무시).
- **직접 입력**: 사내/개인 프록시가 있다면 `https://내프록시/?target={url}` 처럼 `{url}` 자리표시자를 넣어 사용하세요.
- **프록시 없음**: 감시 대상이 **CORS를 허용**하거나 **같은 출처**라면 가장 빠르고 정확합니다.
- 공개 프록시에 민감한(로그인 필요) 페이지 주소를 넣지 마세요. 안정적인 운영에는 자체 프록시를 권장합니다.

### "Failed to fetch" / "모든 프록시 실패" 가 뜬다면
1. **자동 모드**인지 확인하세요(기존 감시는 실행 시 자동으로 업그레이드됩니다). 단일 프록시는 그 프록시가 죽으면 그대로 실패합니다.
2. 잠시 후 다시 시도하세요 — 공개 프록시는 가끔 일시적으로 다운/혼잡합니다.
3. 그래도 안 되면 **Jina Reader** 또는 **직접 입력(자체 프록시)** 를 선택하세요.
4. 대상 사이트가 봇/프록시 IP를 차단하거나 로그인이 필요한 경우, 공개 프록시로는 가져올 수 없습니다.
5. 너무 짧은 주기(예: 5초)는 프록시 사용량 제한에 걸릴 수 있으니 30~60초 이상을 권장합니다.

## 제한 사항

- 감시는 **이 탭이 열려 있는 동안에만** 동작합니다. (브라우저가 닫히면 멈춤)
- 백그라운드 탭에서는 브라우저가 타이머 주기를 늦출 수 있습니다.
- 로그인이 필요한 페이지나 JS로 나중에 그려지는(클라이언트 렌더링) 영역은 정확히 감지되지 않을 수 있습니다.
- 24시간 무중단/탭 없이 감시하려면 서버·크론 등 백엔드 방식이 필요합니다. (이 도구의 범위 밖)
